노드/코덱 가이드 변경분을 검증한다. 이 커맨드는 **검증 전용**이다 — 문서를 수정하지 말고 결과만 보고한다.

> 이 검증은 가이드를 작성한 세션과 **별도의 새 세션**에서 실행해야 한다. 같은 세션에서 실행된 것으로 보이면(이 대화에 가이드 작성 이력이 있으면) 그 사실을 먼저 지적하고, 계속할지 확인받는다.

## 절차

1. **변경분 추출**: `git diff master...HEAD`(브랜치 작업 중) 또는 `git diff HEAD`(커밋 전)로 변경된 가이드 문서를 파악하고, 변경분에서 사실 서술을 목록화한다. 사실 서술이란 코드로 참·거짓을 판정할 수 있는 것이다:
   - 속성명, 필수 여부, 기본값, 허용 값/범위
   - 동작 방식 서술(예: 윈도우 처리, 집계 방식, 에러 처리)
   - 지원 형식, 제약 조건, 버전 요건

2. **코드 경로 확보**: 구현 코드 저장소 경로가 컨텍스트(`CLAUDE.local.md` 등)에 없으면 개발자에게 요청한다. 경로 없이는 3단계를 진행하지 않는다.

3. **코드 대조**: 각 사실 서술에 대해 코드에서 근거를 직접 찾는다. 보수적 기준을 적용한다:
   - 근거를 찾지 못한 서술은 "맞을 것 같다"로 넘기지 말고 **근거 못 찾음**으로 분류한다.
   - 문서와 코드가 다르면 코드 쪽 근거(파일 경로, 해당 정의)를 함께 기록한다. 단, 보고서에 내부 코드 경로를 적는 것은 괜찮지만 코드 내용을 길게 인용하지 않는다.

4. **문서 내 일관성 검토**: 같은 문서의 기존 노드/코덱 섹션과 비교한다:
   - 섹션 구성과 표 컬럼이 기존 섹션과 같은가
   - 같은 개념에 같은 용어를 쓰는가 (기존 섹션과 다른 단어를 새로 도입했는가)
   - 문체·존칭이 기존과 일치하는가

5. **보고**: 결과를 세 분류로 정리해 보고한다. 각 항목에 문서 위치(파일:줄)를 명시한다.
   - ✅ **확인됨**: 코드 근거를 찾았고 일치
   - ❌ **코드와 불일치**: 코드와 다름 — 무엇이 어떻게 다른지, 코드 근거 위치
   - ⚠️ **근거 못 찾음**: 코드에서 확인 불가 — 개발자 직접 확인 필요

   마지막에 일관성 검토 결과(4단계)를 별도 목록으로 붙인다. 문제가 하나도 없으면 그렇게 보고하고 끝낸다 — 억지로 지적 사항을 만들지 않는다.
